# Headroom 0.2 implementation handover

Implemented 15 October 2026 from the [app assessment](app-assessment-2026-10-15.md). This describes source changes; it is not evidence of a deployed server or an installed Android release.

## Roadmap status

| Area | Implemented |
| --- | --- |
| First value | Four-step resumable manual setup, provisional/confirmed baseline, targeted next action, no bank required |
| Examples | Separate persisted personal/example plans, transactions, rules, coverage and move scenarios; realistic fictional review data; switching preserves personal work |
| Data trust | Explicit month attestations, no typed reviewed-month count, imported date-range disclosure, per-bank outcomes, complete-import timestamp only when every outcome is successful/cached, identical-reimport coverage retention |
| Review | Virtualised transaction rows, exact-pence amounts, month navigation, merchant/account/category filters, review queue, batch actions, detail sheet, undo, exact-merchant rules, possible-transfer suggestions and manual cash/unsupported-account entries |
| Plan | Named debts with individual APRs; named goals and combined funding pool; annual-to-monthly bill helper; live validated numeric edits; baseline confirmation; reviewed actuals with explicit application |

| Connections | Typed account/bank/outcome state, saved status hydration and resume refresh, searchable discovery, request busy guards, local-data retention on disconnect, distinct consent success/cancellation and return-to-app link |
| Pairing | Two-minute one-use high-entropy tickets generated by an authenticated server command; paste-to-pair interface; manual token entry under Advanced; pairing kept out of backups |
| Settings | Appearance, reduced motion, optional Move, hide amounts, device authentication, secure-window screen protection, export/validated restore, separate workspace deletion, rule management and explanations |
| Material foundation | Semantic light/dark colours, optional Android 12+ system palette, shared type/shape/layout styles, tonal hierarchy, labelled icon navigation, large-window rail and native press feedback |
| Motion | Restrained navigation transitions, spring-settled transaction sheet with drag dismissal, reduced-motion handling, explicit sync state and undo feedback |
| Recoverability | Safe legacy migration, no overwriting a corrupt/unsupported saved record, visible saving/error status with retry, validated restore confirmation and old house-key cleanup after successful persistence |

The implementation remains React Native. It does not claim complete Compose Material3 Expressive component parity. Wallpaper colours use Android platform palette resources; native screenshots and contrast across actual palettes still need checking. The native icon import is limited to the icon family used by navigation.

The existing finance thresholds and house-calculation engines remain the planning rules. The score is a user-attested planning heuristic. Imports do not silently change the baseline or prove complete statements. Rules are exact merchant matches and respect debit/credit treatment compatibility; transfer suggestions require user confirmation. Goal funding is a combined pool, not an automated priority schedule or payment instruction.

One-use pairing is a personal-server provisioning flow, not multi-user registration or a token revocation system. Forgetting a device removes its local pairing; disconnecting a bank revokes provider consent. Replacing the server device token is still an operator task.

- Dependency installation reports npm advisories in the Expo/React Native/tooling tree. No forced downgrade or unrelated dependency overhaul was performed. Those reports require separate compatibility-aware remediation; this release is not represented as audit-clean.

These are environment limits, not claims of an application failure. No server has been deployed or bank account connected during implementation.

## Native acceptance checks before release

1. Start from a new install: complete and resume setup, reach a provisional result without pairing, confirm the baseline and exercise zero-income/incomplete cases.
2. Upgrade an existing install: verify the plan, reviews and house data; confirm the old typed score evidence is withheld; export a backup before destructive checks.
3. Switch repeatedly between personal and examples; edit both; relaunch. Test switching while a bank import finishes. Personal figures must remain intact and real imports must not enter examples.
4. Enter decimal values, unfinished values and out-of-range inputs. Valid edits must retain the cursor/draft; invalid edits must explain the problem and prevent primary confirmation. Check keyboard visibility and large text.
5. Review mixed credit/debit transactions, bulk edits, exact-merchant rules, refunds, transfer suggestions and undo. Reimport identical and changed data. Confirm month attestations behave correctly.
6. Pair with the HTTPS server using a fresh ticket; test reuse and expiry. Complete, cancel and abandon consent; verify the return link and manual fallback. Check partial sync, expired consent, offline behaviour and retry.
7. Save a backup to an Android folder, inspect its contents, restore it, and reject malformed/oversized backups. Confirm no device/server credentials are exported. Check file picker cancellation and storage failures.
8. Enable enrolled-device authentication, background/resume and relaunch. Test cancellation and credential fallback. Verify screenshot/app-switcher blocking on the target Android version. These controls do not constitute database encryption.
9. Test light/dark/system and Android 12+ wallpaper palettes, 200% text, TalkBack, reduced motion, navigation back behaviour, sheet dismissal/focus and narrow/landscape/tablet layouts. Profile scroll and transitions on a modest phone.
10. Confirm Move inputs, fees, mortgage inclusion gates, saved-scenario loading, cash timing and stress outputs against known fixtures. No lender approval or wider jurisdiction support is implied.

Longer-term features that need additional product/data work remain explicit: recurring-payment forecasting, background imports/notifications, multi-user hosting and automatic evidence reconciliation. No placeholder settings for those have been added. Product analytics are not transmitted.
